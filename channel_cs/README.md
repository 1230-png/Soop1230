# channel_cs — 「다시 배우는 CS」 (미완성 · 2026-09-21 중단)

CS 기초를 다루는 롱폼 채널로 계획했다. **아직 한 편도 발행하지 않았고,
워크플로도 없다.** 지금 상태로는 돌아가지 않는다.

## 왜 롱폼이었나

숏폼 시청 시간은 파트너 프로그램의 3,000시간에 집계되지 않는다. 앞 채널이
61일 동안 숏츠로 13,848회를 모으고도 시청 시간 기여는 사실상 0이었다.
같은 관객을 30분 영상 지속률 40%에 태우면 1회당 12분이 쌓여, 3,000시간까지
필요한 조회수가 300만에서 1.5만으로 내려간다. 형식이 주제보다 먼저다.

## 왜 멈췄나

**결과물이 자동 생성 티가 너무 난다.** 검은 배경 슬라이드에 edge-tts 한국어
음성을 얹은 형태인데, 이 조합은 3초 안에 알아볼 수 있다. 대본을 잘 써도
그 3초에서 이미 분류가 끝난다.

취향 문제로 끝나지 않는다. 유튜브의 inauthentic content 정책이 정확히 이
형태 — 전편 TTS + 템플릿 화면 — 를 걸러 낸다. 목표가 수익화인데 형식이
심사에서 막힐 모양이면 나머지는 의미가 없다.

원인은 코드가 아니라 조건이다. 「무료 + 컴퓨터가 꺼져 있어도 + 사람 개입
없이」 셋을 동시에 만족시키면 기계가 만든 티가 나는 결과밖에 나오지 않는다.
더 잘 만들어서 없어지는 문제가 아니다.

**되살리려면 사람 목소리가 필요하다.** 대본·슬라이드·인코딩·업로드·스케줄은
이 코드가 그대로 한다. 바뀌는 것은 `build.py` 의 `tts.synthesize` 자리를
미리 녹음한 파일로 바꾸는 것 하나다. 20분짜리 한 편에 녹음 25~30분,
주 2편이면 주당 한 시간이 사람 몫이 된다.

## 지금 있는 것

| 파일 | 상태 |
|---|---|
| `curriculum.yaml` | 채널 이름·설명·키워드, 시즌 4개와 20편 목록 |
| `episodes/E01-segfault.yaml` | 1편 대본 전체 (장면 19개, 실측 13분 — 목표 18분에 미달) |
| `lib/cards.py` | 카드 렌더러. 코드·터미널·도식·제목·썸네일 |
| `lib/tts.py` | `channel_jp` 에서 그대로 복사 |
| `build.py` | 대본 → 영상. `--offline` 으로 합성 없이 배치만 확인 가능 |
| `upload.py` | `channel_jp/upload.py` 본. `CS_*` 전용, **대체 자격 증명 없음** |
| `get_refresh_token.py` | 1회용. 본인 컴퓨터에서 돌린다 |

없는 것: 테스트, 워크플로, 2편 이후 대본, 구글 클라우드 프로젝트.

## 확인된 것과 확인 못 한 것

확인됨: `--offline` 빌드가 끝까지 돈다(19장면 775초). 카드 렌더러가 코드·
터미널·도식·제목을 제대로 그린다.

**확인 불가**: 실제 TTS 빌드. 이 컨테이너의 프록시가 자체 서명 인증서를
쓰는데 edge-tts 는 그것을 신뢰하지 않아 `speech.platform.bing.com` 연결이
막힌다. 그래서 **실제 영상 길이와 소리는 한 번도 확인하지 못했다.**
`--offline` 은 글자 수로 길이를 짐작할 뿐이다(초당 7자 가정, 한국어 실제
발화는 더 느리다).

## 코드 카드는 ASCII 만 받는다

PIL 은 글자마다 대체 글꼴을 찾아 주지 않는다. 고정폭 글꼴에 한글이 없으면
□ 로 그려진다. 그래서 `code` · `command` · `output` 에 ASCII 가 아닌 글자가
있으면 `build.py` 가 합성을 시작하기 전에 멈춘다. 한국어 설명은 카드 아래
`caption` 줄에 넣는다.

## 이름

계획 문서에는 `channel_rush/` 로 적혀 있었다. 채널 이름을 「다시 배우는 CS」로
정하면서 디렉터리도 맞췄다 — `rush` 는 지우기로 한 앞 채널의 이름이라
그대로 두면 다음 사람이 두 채널을 같은 것으로 읽는다.
