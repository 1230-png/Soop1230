# market-verify

**채널: 머니로직 MoneyLogic.** 채널 이름·소개·면책 문구는 `src/brand.py` 에서만 고친다.

채널이 다루는 갈래는 셋이다.

1. 가상자산 네트워크 기술 및 토크노믹스 해부
2. 매크로 경제 지표와 유동성 데이터 분석
3. 수학적 투자 전략(분할 매수, 리밸런싱 등)의 메커니즘 검증

**`market-verify` 는 2번과 3번을 만든다** — 1번(토크노믹스)은 아직 도구가 없다.
이 파일을 채널 전체 파이프라인으로 착각하지 말 것.

주식·지수·코인의 **과거 사례 검증** 롱폼 대본을 만드는 파이프라인.
매일 시황 요약은 하지 않는다. 유튜브 양산형 콘텐츠 정책에 걸리고 검색 유입도 없다.
"지금 상황이 과거에 몇 번 있었고 그때 어떻게 됐는지"만 수치로 보여주는 에버그린 구조다.

## 설계 판단 (이유까지 지킬 것)

1. **숫자는 코드가 뽑는다.** LLM은 과거 시계열 수치를 지어낸다.
   `market_events.py`가 데이터 블록을 만들고, 모델은 그 블록을 받아 대본만 쓴다.
2. **규칙 검증은 코드가 한다.** 모델에게 자체 점검을 시켰더니 위반해놓고 O를 찍었다.
   `validator.py`의 판정만 신뢰한다. 모델의 자기 보고는 근거로 쓰지 않는다.
3. **[운영자 코멘트]는 사람이 채운다.** 채널의 진정성 확보 지점이다.
   모델이 채우면 위반으로 잡는다 (`validator.py` 6번 항목).
4. **예측·매수매도 추천·목표가를 생성하지 않는다.** 국내 유사투자자문 규제 때문이다.

## 네 가지 도구 — 채널의 세 갈래를 모두 덮는다

**조건 검증** (`run.py`) — "이 조건이 과거에 몇 번 있었고 그 뒤 분포가 어땠나".

**전략 검증** (`run_strategy.py`) — "같은 돈을 다르게 넣으면 결과가 어떻게 갈렸나".
채널 세 번째 갈래(수학적 투자 전략의 메커니즘 검증).

**매크로 검증** (`run_macro.py`) — "지표가 이 상태였던 시점 이후 자산이 어떻게 움직였나".
채널 두 번째 갈래(매크로 경제 지표와 유동성 데이터 분석).

**토크노믹스** (`run_tokenomics.py`) — "공급이 어떤 규칙으로 늘고, 그동안 무엇이 달라졌나".
채널 첫 번째 갈래(가상자산 네트워크 기술 및 토크노믹스 해부).

```bash
# 발행 스케줄 해부 — 외부 데이터를 전혀 받지 않는다
python -m src.run_tokenomics --mode schedule --asset '비트코인' --block-only

# 실측 희석률 — 코인게코, 키 불필요
python -m src.run_tokenomics --mode dilution --coin bitcoin --asset '비트코인' --block-only
```

### 발행 스케줄은 왜 API 를 쓰지 않는가

비트코인 공급 곡선은 합의 규칙이다. 210,000블록마다 보상이 절반이 되고, 그래서
총 발행량이 21,000,000 으로 수렴한다. 누가 발표하는 수치가 아니라 코드로 정해진
값이므로 계산한다. 외부 데이터에 기대면 그쪽이 틀렸을 때 이쪽도 틀린다.

테스트가 총 발행량 21,000,000 과 반감기마다 발행량이 정확히 절반이 되는 것을
못박아 둔다. 여기서 어긋나면 계산이 깨진 것이다.

**첫 구간의 인플레이션율은 비워 둔다.** 이전 공급이 0이라 비율을 낼 수 없다.
0으로 적으면 거짓말이 된다.

**과거 반감기 날짜는 기록, 미래는 추정이다.** `RECORDED_HALVINGS` 에 실제 날짜를
두고, 미도래 구간은 "미도래"로 적는다. 블록에 추정을 사실처럼 섞지 않는다.

### 코인게코는 무료 티어에도 키가 필요하다

`COINGECKO_API_KEY` 를 넣지 않으면 401 을 돌려준다. 키가 없으면 요청 전에 멈추고
안내한다 — 다 만들고 나서 실패하면 시간만 버린다. 발행 스케줄 모드는 이 키가
필요 없다. 합의 규칙에서 계산하기 때문이다.

401·404·429 를 상태 코드만 던지지 않고 무엇을 고쳐야 하는지로 바꿔 알려준다.

`interval=daily` 는 유료 플랜에서만 받는 경우가 있어 뺐다. 빼도 기간에 맞춰
알아서 일간으로 준다. 무료 티어는 받을 수 있는 기간도 짧을 수 있는데, 기록이
`--periods` 보다 짧으면 그렇게 말해 준다. 그때는 `--periods 90` 처럼 줄이면 된다.

### 유통량을 왜 시총 ÷ 가격으로 유도하는가

코인마다 유통량 공시 기준이 다르고 갱신 시점도 어긋난다. 시가총액과 가격은 같은
스냅샷에서 나오므로, 둘을 나누면 두 값을 따로 받아 붙이는 것보다 어긋나지 않는다.

연 단위로 한 점씩만 뽑는다. 매일 찍으면 표가 수천 줄이 되고 대본이 읽을 수 없다.

```bash
# 장단기 금리차가 0 아래로 내려간 시점 이후 S&P 500
python -m src.run_macro --series T10Y2Y --below 0 \
  --ticker '^GSPC' --label 'S&P 500' --start 1990-01-01 --block-only

# M2 통화량 증가율이 마이너스로 돌아선 시점 이후
python -m src.run_macro --series M2SL --yoy 12 --below 0 \
  --ticker '^GSPC' --label 'S&P 500' --start 1990-01-01 --block-only
```

지표는 FRED(무료, `FRED_API_KEY` 발급 필요), 결과는 야후에서 받는다.

### 왜 상관계수를 내지 않는가

상관은 인과로 읽힌다. "유동성이 늘면 자산이 오른다"는 문장은 이 채널이 하지 않기로
한 예측에 한 발 걸친다. 그래서 조건 검증과 같은 방식만 쓴다 — 지표가 그 상태였던
시점을 세고, 그 뒤 분포를 보여주고, 결론은 시청자가 낸다.

### 두 시계열을 어떻게 붙이는가

지표는 월간·주간이고 발표일이 휴장일일 수 있다. 그 날짜로 바로 수익률을 계산하면
없는 가격을 참조한다. `to_trading_days()` 가 지표일 이후 **첫 거래일**로 민다.
여러 지표일이 같은 거래일로 몰리면 하나로 합친다.

그 뒤 조건 검증과 같은 60거래일 간격 필터를 건다. 월간 지표는 조건이 연달아 걸려서
필터가 없으면 표본이 부풀어 오른다.

FRED 는 결측을 `.` 으로 준다. 0 으로 읽으면 "0 이하로 내려갔다"가 엉뚱하게 걸리므로
버린다. 테스트가 이걸 못박아 둔다.

## (구) 두 가지 검증

**조건 검증** (`run.py`) — "이 조건이 과거에 몇 번 있었고 그 뒤 분포가 어땠나".

**전략 검증** (`run_strategy.py`) — "같은 돈을 다르게 넣으면 결과가 어떻게 갈렸나".
채널의 세 번째 갈래(수학적 투자 전략의 메커니즘 검증)가 여기 해당한다.

```bash
python -m src.run_strategy --ticker '^GSPC' --start 1990-01-01   --contrib-months 12 --hold-months 36 --label 'S&P 500' --block-only
```

둘은 검증기·작성기·영상 파이프라인을 그대로 공유한다. 대본 헤더 구조가 같아서
프롬프트도 하나로 쓴다. 다른 것은 블록 안의 표뿐이다.

### 분할 매수 대 일시 매수를 어떻게 재는가

같은 날 시작해 **같은 날 끝낸다.** 끝나는 날이 다르면 비교가 성립하지 않는다.
분할 매수는 매달 1/N 씩 넣고 남은 기간은 그대로 들고 간다.

`contrib_months=1` 이면 분할 매수가 일시 매수와 정확히 같아진다. 테스트가 이걸
못박아 둔다 — 시뮬레이션이 어긋나면 여기서 먼저 깨진다.

시작 시점도 겹치지 않게 126거래일씩 띄운다. 조건 검증의 60거래일 필터와 같은
이유다. 창이 겹치면 한 국면이 표본 수십 개로 부풀어 "과거 200번 중" 같은 말이 된다.

**승률만 내지 않는다.** 분할 매수가 앞선 비율과 함께 양쪽의 분포를 다 낸다.
합성 데이터에서도 이미 드러난다 — 일시 매수는 중앙값이 높지만 최저가 훨씬 깊고,
분할 매수는 중앙값이 낮은 대신 최저가 얕다. 어느 쪽이 낫다고 말하지 않는다.
그건 시청자가 정한다.

### 리밸런싱 주기를 어떻게 재는가

같은 시작 시점에서 **주기만 바꿔** 굴린다. 비교 대상이 하나만 달라야 원인을 짚을 수 있다.

**수익률만 비교하면 요점을 놓친다.** 리밸런싱은 수익을 늘리는 장치가 아니라 비중이
한쪽으로 쏠리는 것을 막는 장치다. 그래서 최대 낙폭을 함께 낸다.

합성 데이터로 확인한 방향은 이렇다. 한쪽만 오르는 구간에서는 리밸런싱이 오른 쪽을
계속 덜어내 **수익이 낮아진다**(잦을수록 더). 출렁이는 구간에서는 **낙폭이 줄어든다**.
둘 다 테스트가 못박아 두었다 — 부호가 뒤집히면 시뮬레이션이 깨진 것이다.

주기가 보유 기간보다 길면 한 번도 리밸런싱하지 않은 것과 같아야 한다. 이것도
테스트로 확인한다.

두 종목은 `align()` 이 공통 거래일로 맞춘다. 상장일도 휴장일도 달라서, 맞추지 않으면
없는 날 가격으로 계산하게 된다.

## 왜 60거래일 필터인가

`apply_min_gap()`이 사례 간 최소 60거래일 간격을 강제한다.
이게 없으면 한 번의 하락장이 사례 20건으로 부풀고, 대본이
"과거에 20번 있었다"는 거짓말을 하게 된다.

## 왜 평균이 아니라 분포인가

`summarize()`는 표본수·중앙값·평균·최저·최고·상승비율을 모두 낸다.
평균만 내면 -30%와 +50%가 +10%로 보인다. 대본은 분포를 먼저 말한다.

## 표본 5건 미만

`to_block()`이 stderr로 경고한다. 5건 미만은 경향이 아니라 우연이므로
그 주는 다른 조건으로 바꾸는 편이 낫다.

## 구조 숫자 허용셋을 왜 3개로 묶어 두는가

헤더 줄과 목록 번호를 지우고 나면 본문에 남는 구조 숫자는 숏폼 컷 번호뿐이다.
`validator.STRUCTURAL_NUMBERS = {"1", "2", "3"}` 가 그것만 통과시킨다.

처음에는 이 목록을 데이터 블록에 `[대본 구조용 허용 숫자]` 줄로 적어 두고
1~7, 12, 60까지 열어 뒀다. 블록에 드러나 검토하기 쉽다는 장점은 있었지만,
허용 숫자 아홉 개가 그대로 환각 탐지의 구멍이 된다. 모델이 "12개월 뒤 7% 올랐다"
같은 문장을 지어내도 12와 7이 허용셋에 있어 통과한다.

그래서 허용셋을 검증기 안으로 옮기고 컷 번호 세 개로 좁혔다.
블록은 이제 실측 수치만 담는다. 여기를 넓히려면 그만큼 탐지가 헐거워진다는 것을
먼저 인정할 것. `test_structural_allowlist_is_only_the_cut_numbers`가 못박아 둔다.

1개월·6개월·12개월의 1, 6, 12는 허용셋이 아니라 블록의 구간 표기
`21거래일(1개월)`에서 그대로 나온다. 별도 허용이 필요 없다.

## 3회 실패하면 그 주는 건너뛴다

`writer.py`는 최대 3회 재시도하고, 매 재시도에 적발된 위반 문구를 그대로 되먹인다.
추상적으로 "형식이 틀렸다"고 하면 다음 시도도 똑같이 틀린다.
3회 모두 실패하면 예외를 던지고 대본을 저장하지 않는다.
틀린 대본을 올리는 것보다 그 주를 건너뛰는 게 낫다.

## 실호출에서 드러난 오탐 두 가지 (2026-09-07)

첫 실제 호출에서 3회 모두 검증에 걸려 대본을 저장하지 못했다. 원인 중 둘은 검증기 잘못이었다.

**하나. 운영자 칸의 마크다운 구분선.** 모델이 `## 6. [운영자 코멘트]` 아래에 `---` 를
넣어 섹션을 나눴는데, 검증기가 이걸 "사람이 채울 칸을 모델이 채웠다"로 잡았다.
3회 모두 이것 때문에 떨어졌고, 2회차는 이 항목 하나만 남아 있었다.
구분선은 코멘트가 아니므로 지우고 본다.

**둘. 블록 날짜의 연도.** 숫자 대조 전에 `YYYY-MM-DD` 를 통째로 걷어내다 보니,
블록에 `1990-01-02` 가 있는데도 대본의 "1990년"이 환각으로 잡혔다.
연도는 블록에 그대로 적혀 있는 값이므로 허용한다. 월·일은 허용하지 않는다 —
그건 날짜를 통째로 인용하면 될 일이고, 열어 주면 오탐 방지가 아니라 탐지 약화가 된다.

나머지 위반(36, 4, 7, 30 등)은 모델이 계산해 만든 숫자였고 정상적으로 잡힌 것이다.
프롬프트에 적발 사례를 그대로 적어 두었다.

**재시도 피드백에 문장을 붙였다.** "블록에 없는 숫자: 36" 만으로는 모델이 어디를
고쳐야 할지 모른다. 이제 그 숫자가 처음 나온 문장을 함께 준다.

**max_tokens 를 8000에서 16000으로 올렸다.** 12~18분 대본이 상한에서 잘리면 그 시도가
통째로 버려진다. 출력 토큰은 생성한 만큼만 과금되므로 천장을 올려도 평소 비용은 그대로다.
잘린 경우 run 이 경고를 찍는다.

## 토큰 사용량과 비용

호출마다 API 응답의 실제 `usage`(입력·출력 토큰)를 찍는다. 추정이 아니라 실측이다.
3회 모두 실패해 대본을 저장하지 않는 경우에도 쓴 토큰은 남겨 출력한다.
실패해도 돈은 이미 나갔기 때문이다.

옆에 붙는 달러 금액은 `writer.PRICE_PER_MTOK` 표로 계산한 **추정치**다.
2026-06-24 기준 공개 요금이고 바뀔 수 있다. 실제 청구액은 Anthropic 콘솔이 기준이다.
요금이 달라지면 그 표만 고치면 된다. 표에 없는 모델을 쓰면 금액 없이 토큰만 찍는다.

주 1회 롱폼 기준 월 $0.3~$1 수준이다. 재시도가 늘수록 비례해서 는다.

## 사용법

```bash
pip install -r requirements.txt
export ANTHROPIC_API_KEY=...        # 코드·커밋에 절대 넣지 않는다

# 데이터 블록만 먼저 확인 (API 호출 없음, 비용 0)
python -m src.run --ticker '^GSPC' --condition down-weeks --n 3 \
  --start 1990-01-01 --label 'S&P 500' --block-only

# 대본까지 생성
python -m src.run --ticker '^GSPC' --condition down-weeks --n 3 \
  --start 1990-01-01 --label 'S&P 500'
```

조건 3종:

| --condition | 인자 | 의미 |
| --- | --- | --- |
| `down-weeks` | `--n` | 주간 종가 N주 연속 하락 (W-FRI 리샘플) |
| `drawdown` | `--pct` | 전고점 대비 -X% 구간 첫 진입 |
| `threshold` | `--level` | 임계값 이상 첫 돌파 (VIX 등) |

산출물은 `out/`에 저장된다 (gitignore). 대본은 검증을 통과했을 때만 저장된다.

## 대본 완성 전 마지막 한 단계

`## 6. [운영자 코멘트]`는 모델이 비운 채로 넘기고, 저장할 때 작성 안내를 HTML 주석으로
넣는다. 업로드 전에 사람이 그 자리에 직접 쓴다.

안내를 넣는 이유: 빈 제목 줄만 남겨 두면 무엇을 쓰라는 건지 알 수 없어서, 실제로
제목 줄을 지우고 그 자리에 문장을 쓰는 일이 있었다. 제목 줄이 사라지면 매주 대본
구조가 달라지고 검증도 안 된다. HTML 주석이라 화면에는 남지 않고, 검증기는 주석을
코멘트 본문으로 세지 않으므로 저장본을 다시 검사해도 통과한다.

이 칸은 면책 문구를 넣는 자리가 아니다. 그건 이미 유튜브 설명란에 있다.
모델이 쓸 수 없는 것, 즉 운영자 본인의 관점을 넣는 자리다.

## 영상 제작 (대본 다음 단계)

```bash
python -m src.produce --script out/..._script.md            # 영상 + 썸네일
python -m src.produce --script out/..._script.md --upload   # 비공개로 업로드까지
```

돈이 들지 않는다. edge-tts, ffmpeg, 유튜브 무료 할당량만 쓴다.

**화면은 대본이 정한다.** 대본에 이미 `[자료 화면: 내용 / 화면 텍스트 "..."]` 표기가
들어 있고, 그게 장면 경계이자 화면에 띄울 문구다. 따로 만들지 않는다.
표기는 설명하는 문장 *뒤*에 붙으므로, 직전까지 읽은 나레이션에 그 문구를 씌운다.
앞뒤로 다 있으면 뒤쪽을 쓴다.

**연출을 넣지 않는다.** 단색 그라데이션에 문구 하나. 공포·탐욕을 자극하는 수식어를
배제한다는 대본 원칙이 화면에도 그대로 적용된다.

**업로드는 기본이 비공개다.** 운영자 코멘트를 채웠는지, 화면이 의도대로 나왔는지
눈으로 보고 나서 사람이 유튜브 스튜디오에서 공개로 바꾼다. `--privacy public` 은
있지만 일부러 기본값에서 뺐다.

`assert_target_channel` 이 토큰이 가리키는 채널을 확인한다. 이 저장소는 채널을
여러 개 운영해서, 토큰을 잘못 넣으면 다른 채널에 올라가고 되돌리려면 손으로 지워야 한다.

`--silent` 는 음성 없이 길이만 맞춘 무음으로 영상을 만든다. 네트워크를 타지 않아
화면 구성만 빠르게 확인할 때 쓴다. TTS 를 주입식으로 둔 것도 같은 이유다 —
edge-tts 가 막힌 환경에서도 영상 조립 전체를 검증할 수 있어야 한다.

## PC 가 꺼져 있어도 돌리기 (GitHub Actions)

`.github/workflows/moneylogic_daily.yml` 이 매일 22:00 UTC(한국 07:00)에 돈다.
전날 미국장 마감(06:00 KST) 뒤라 어제 움직임이 다 들어온 시각이다.

**대본은 구독으로 쓴다. API 크레딧이 필요 없다.**

```bash
claude setup-token     # 내 PC 에서 한 번. 구독 계정으로 장기 토큰을 만든다
```

나온 값을 저장소 **Settings → Secrets and variables → Actions** 에

무엇을 넣어야 하는지 찍는다.

**결과물은 아티팩트로 나온다. 업로드는 하지 않는다.** Actions 실행 화면에서
`moneylogic-<번호>` 를 받으면 영상·썸네일·대본이 들어 있다. 사람이 운영자 코멘트를
채우고 올린다. 무인 발행으로 바꾸고 싶으면 비공개 기본값과 `assert_target_channel`
이 왜 있는지 먼저 읽을 것.

**예약 실행은 기본 브랜치에서만 걸린다.** 깃허브 규칙이다. 이 워크플로가 다른
브랜치에 있는 동안에는 손으로 돌리는 것(Run workflow)만 된다.

**다룬 소재는 워크플로가 커밋한다**(`used_topics.csv`, `[skip ci]`). 이게 남아야
다음 회차가 같은 소재를 피한다.

## 매일 돌리기 (daily_pipeline) — 소재만 바꾸고 형식은 그대로

```bash
python -m src.daily_pipeline                    # 다음 토픽으로 롱폼 + 숏폼까지
python -m src.daily_pipeline --repeat 2          # 한 번에 두 편 (편마다 다음 토픽)
python -m src.daily_pipeline --block-only        # 블록까지만 (비용 0)
python -m src.daily_pipeline --silent            # 무음으로 조립까지 확인
python -m src.daily_pipeline --outdir "D:\MoneyLogic\out"
python -m src.daily_pipeline --topic-key btc-dilution
```

`--repeat` 는 **첫 실패에서 멈춘다.** 무인으로 도는 자리라, 같은 원인(키 만료·한도
초과)으로 남은 편까지 토큰을 태우는 것을 막는다. 몇 편까지 만들고 멈췄는지 찍는다.

**매일 시황 요약은 여전히 하지 않는다.** 위(맨 앞)에 적은 이유가 그대로다 —
양산형 정책에 걸리고 검색 유입도 없다. 여기서 매일 바뀌는 것은 "오늘의 시황"이
아니라 딥다이브 **대상**(자산·지표·조건)이다. 형식은 언제나 "이 조건이 과거에 몇 번
있었고 그 뒤 분포가 어땠나"는 에버그린 구조 그대로다. 소재가 매일 다른 것과
매일 시황을 읊는 것은 다른 일이다.

소재는 두 곳에서 온다(`--source`).

**`news`(기본) — 어제 실제로 크게 움직인 자산.** `src/news_topics.py` 가 감시 목록의
어제 종가 변화율을 재서 가장 크게 움직인 것을 오늘 대상으로 삼는다. **뉴스 문장을
읽지 않는다** — 기사 요약은 이 채널이 안 하기로 한 것이고, 모델이 기사 내용을 지어낼
여지도 있다. 화제의 근거를 숫자로 두면 검증이 된다. 고른 뒤 만드는 것은 여전히
"이 조건이 과거에 몇 번 있었나"는 에버그린 검증이다. 소재만 어제에서 가져온다.

1.5% 미만으로 조용한 날에는 풀로 넘긴다. **어제 별일 없었는데 억지로 화제를
만드는 것이 제일 나쁘다.**

**`pool` — 순환 풀.** `src/topics.py` 의 `TOPIC_POOL` 하나가 원장이다. 순서대로
소진하고 전부 돌면 처음으로 돌아간다.

어느 쪽이든 이미 다룬 것은 `used_topics.csv`(append-only, 다른 채널의
`used_log*.csv` 와 같은 관례)로 건너뛴다.

**업로드는 이 파이프라인이 하지 않는다.** `produce.build()` 만 부르고 업로드 경로는
아예 타지 않는다. 결과를 눈으로 보고 사람이 `src.produce --upload` 로 올린다.
무인 발행으로 바꾸고 싶어지면, 비공개 기본값과 `assert_target_channel` 이 왜 있는지
먼저 읽을 것.

**블록만 만든 실행은 다룬 것으로 기록하지 않는다.** 영상까지 나와야 그 소재를
썼다고 본다. 중간에 실패한 실행도 마찬가지다.

### 숏폼은 롱폼 대본에서 잘라낸다

대본의 `## 숏폼 컷 3개` 는 원래 사람이 보고 자르라고 둔 지시문이었다.
`src/shorts.py` 가 그 지시문의 시작·끝 문구를 장면 목록에 그대로 대입해 자동으로
잘라낸다. 화면 문구를 새로 짓지 않는 것과 같은 이유로, **문구를 새로 판단하지 않고
대본에 있는 것만 찾는다. 못 찾으면 추측하지 않고 그 컷을 건너뛴다.**

세로 캔버스는 `render.slide()` 에 크기만 다르게 넘겨서 만든다. 그리기 로직이
가로·세로가 같아서 따로 만들지 않았다 — 두 벌이 되면 한쪽만 고치는 일이 생긴다.

**컷 지시문의 모양은 믿지 않는다.** 프롬프트가 형식을 적어 주고 검증기는 헤더만
보기 때문에, 모델이 매번 같은 모양으로 쓰지 않는다. 라벨 모양을 맞히려던 파서가
한 회차를 통째로 숏폼 0개로 끝냈다. 지금은 **섹션 안에 인용된 문장을 등장 순서대로
짝짓는다** — `시작:` / `**시작**:` / `- 시작 문장:` / 화살표 / 따옴표만 있는 줄이
모두 같은 결과로 읽힌다. 잘못 짝지은 컷은 본문에서 문구를 못 찾아 건너뛰므로,
형식을 좁게 잡아 전부 놓치는 쪽보다 안전하다.

본문과 인용을 맞출 때도 띄어쓰기·따옴표·문장부호 차이는 무시한다. 모델이 본문을
옮겨 적으면서 그런 것들을 바꾼다. 다만 짧은 조각까지 느슨하게 맞추면 엉뚱한 장면이
걸리므로 길이가 되는 것만 그렇게 한다(`MIN_LOOSE_MATCH`).

숏폼이 0개로 끝나면 로그에 `!` 줄이 찍히고, 깃허브 액션 요약에도 편수가 남는다.
조용히 0개로 넘어가는 것이 가장 나쁘다 — 며칠이 지나서야 알아챈 적이 있다.

### 대본을 누가 쓰는가 — API 키 대신 구독으로도 된다

`MARKET_VERIFY_LLM` 하나로 갈린다.

| 값 | 대본 작성자 | 드는 것 |
|---|---|---|
| (없음, 기본) | anthropic SDK | `ANTHROPIC_API_KEY` + **API 크레딧**(선불 충전) |
| `cli` | 이미 깔린 Claude Code(`claude -p`) | **구독 사용량** (키·크레딧 불필요) |

```bash
set MARKET_VERIFY_LLM=cli        # 윈도우
export MARKET_VERIFY_LLM=cli     # 맥·리눅스
```

구독과 API 크레딧은 **별도 지갑**이다. claude.ai 를 구독 중이어도 API 크레딧은
따로 충전해야 하는데, `cli` 모드는 그 충전 없이 이미 내고 있는 구독으로 돌린다.

갈아끼우는 자리는 `writer.default_client()` 하나다. `write_script()` 가 원래
클라이언트를 인자로 받게 돼 있어서, 검증·재시도·피드백 루프는 그대로 돈다.
`src/cli_client.py` 가 `claude -p --output-format json` 을 부르고 응답을 SDK 와
같은 모양으로 돌려준다.

**데이터 블록은 표준입력으로 넣는다.** 윈도우 명령줄이 약 8191자에서 잘리는데
블록은 그보다 길 수 있다. 인자로 넘기면 조용히 잘린 블록으로 대본을 쓰게 된다.

**공짜는 아니다.** 구독 사용량을 깎는다. 무인으로 많이 돌리면 평소 쓰는 한도에
영향이 간다. 그리고 로그인이 풀리면 그 회차가 실패한다 — 그때는 사람이 한 번
`claude` 를 실행해 로그인해야 한다. 실패 메시지가 그렇게 안내한다.

### 윈도우에서 자동으로 만들기 (작업 스케줄러)

`scripts/make_longform.bat` 이 스케줄러가 부르는 자리다. 준비물(파이썬·ffmpeg·
`ANTHROPIC_API_KEY`)을 **만들기 전에** 확인하고, 실행 기록을 `<폴더>\_log\` 에 남긴다.
무인으로 도는 자리라 로그가 없으면 왜 실패했는지 알 방법이 없다.

1. 준비물을 깐다.

```powershell
winget install Python.Python.3.12
winget install Gyan.FFmpeg          # 설치 후 새 창을 열어야 PATH 가 잡힌다
git clone https://github.com/1230-png/Soop1230.git
cd Soop1230\market-verify
python -m venv .venv
.venv\Scripts\pip install -r requirements.txt
setx ANTHROPIC_API_KEY "sk-ant-..."   # 키는 환경변수로만 둔다. 파일에 적지 않는다.
```

2. `scripts\make_longform.bat` 위쪽의 `OUTDIR`(저장 폴더)과 `COUNT`(한 번에 몇 편)를
   고친다. 먼저 손으로 한 번 돌려 보고 영상이 나오는지 확인한다.

3. 주 3회(월·수·금 오전 9시)로 등록한다. 경로는 실제 위치로 바꿀 것.

```powershell
schtasks /Create /TN "MoneyLogic 롱폼" /SC WEEKLY /D MON,WED,FRI /ST 09:00 ^
  /TR "\"C:\Soop1230\market-verify\scripts\make_longform.bat\"" /RL LIMITED
```

주 2회면 `/D MON,THU`, 매일이면 `/SC DAILY`. 지우려면 `schtasks /Delete /TN "MoneyLogic 롱폼"`.

**노트북이 꺼져 있으면 그 회차는 그냥 넘어간다.** 작업 스케줄러는 놓친 실행을
기본적으로 따라잡지 않는다. 다음 회차에 다음 토픽으로 이어서 만든다 —
`used_topics.csv` 가 어디까지 썼는지 알고 있어서 같은 소재가 두 번 나오지는 않는다.

**토픽 풀이 소진되면 처음으로 돌아간다.** 주 3편이면 10개짜리 풀이 3주가 조금 넘는다.
계속 돌릴 생각이면 `src/topics.py` 의 `TOPIC_POOL` 에 소재를 더 넣어야 한다.
FRED 시리즈 ID·티커는 실제로 존재하는 것만 넣을 것 — 없는 ID 를 적으면 그날 회차가
통째로 실패한다.
