# @Rush22 «머니러시» — 설정 가이드

채널: https://www.youtube.com/@Rush22-i8p
포맷: **머니러시** — 하루 30초, 돈이 되는 생활경제 상식 쇼츠.

한 편은 세 장면으로 구성됩니다.

| 장면 | 역할 | 길이 |
|---|---|---|
| hook | 스크롤을 멈추게 하는 질문 한 줄 | 3~5초 |
| body | 실제 설명 | 15~20초 |
| punch | 한 줄 결론 + 구독 유도 | 5~8초 |

장면마다 배경색과 문구가 바뀌므로 한 장짜리 정지 화면보다 이탈률이 낮습니다.
현재 콘텐츠 뱅크 60편 기준 실제 길이는 **편당 25~33초**입니다.

---

## 자동으로 돌아가는 것

| 워크플로우 | 스케줄 | 하는 일 |
|---|---|---|
| `.github/workflows/run_rush22.yml` | 매일 07:00 / 18:00 KST | 쇼츠 1편 생성 + 업로드 |

매 실행마다: `content_bank.json`에서 아직 안 쓴 항목 선택 → 장면 3개 렌더링
(Pillow) → 내레이션 생성(edge-tts) → ffmpeg로 장면별 합성 후 이어붙이기 →
YouTube 업로드 → `used_log.csv`에 기록 후 자동 커밋.

하루 2편이면 60편으로 **약 30일** 돌아갑니다. 소진되면 처음부터 다시 순환하되
로그에 경고를 남기므로, 그 전에 `content_bank.json`에 항목을 추가하세요.

> **중요:** GitHub는 **기본 브랜치에 있는 워크플로우 파일의 `cron`만** 인식합니다.
> 이 파일이 기본 브랜치에 병합되기 전까지는 스케줄이 돌지 않고, Actions 탭에서
> 수동 실행(**Run workflow**)만 가능합니다.

## 필요한 GitHub Secrets

저장소 → Settings → Secrets and variables → Actions

| Secret 이름 | 필수 | 설명 |
|---|---|---|
| `RUSH_CLIENT_ID` | ✅ | Google Cloud OAuth 클라이언트 ID |
| `RUSH_CLIENT_SECRET` | ✅ | 〃 보안 비밀번호 |
| `RUSH_REFRESH_TOKEN` | ✅ | 아래 3단계에서 발급 |
| `RUSH_CHANNEL_ID` | 선택 | 채널 ID로 업로드 대상을 고정 (권장) |

**이름이 `RUSH_`로 시작하는 이유:** 이 저장소의 다른 채널도 유튜브에 업로드합니다.
과거에 여러 채널이 `YT_*` 시크릿 하나를 공유하다가 한쪽 자격증명을 교체하는
순간 다른 채널 업로드가 전부 깨진 적이 있습니다. 더 나빴을 수도 있습니다 —
교체가 반대 방향이었다면 **이 채널 영상이 남의 채널에 올라갔을** 겁니다.

그래서 `upload_video.py`에는 **폴백이 없습니다.** `RUSH_*`가 없으면 다른 채널
자격증명을 빌려 쓰는 대신 그 자리에서 실패합니다. 업로드 직전에 자격증명이
정말 `@Rush22-i8p` 것인지도 한 번 더 확인합니다.

## 처음부터 세팅하기

### 1. Google Cloud 프로젝트 만들기

1. https://console.cloud.google.com → **새 프로젝트** 생성 (무료)
2. "API 및 서비스" → "라이브러리" → **YouTube Data API v3** 사용 설정

> ⚠️ **이 채널만의 새 프로젝트를 만드세요.** YouTube Data API 무료 할당량은
> **채널이 아니라 프로젝트 단위로 하루 10,000 유닛**입니다. 업로드 1회가 약
> 1,600 유닛이라 `@200-y3b`(하루 3편, 4,800)와 한 프로젝트를 같이 쓰면
> 이 채널 2편(3,200)까지 8,000, 여기에 주간 롱폼까지 겹치는 일요일엔
> 한도에 닿습니다. 프로젝트를 나누면 각각 10,000씩 받고 이 문제가 사라집니다.
> 프로젝트 추가는 무료이고 카드 등록도 필요 없습니다.

### 2. OAuth 클라이언트 만들기

3. "OAuth 동의 화면": User Type **외부**, 테스트 사용자에 `@Rush22-i8p`
   관리 계정을 추가
4. "사용자 인증 정보" → "OAuth 클라이언트 ID" → 애플리케이션 유형 **데스크톱 앱**
   → **클라이언트 ID**와 **보안 비밀번호** 복사

> 보안 비밀번호는 생성 직후에만 전체가 보입니다. 놓쳤으면 클라이언트 상세 화면의
> **"+ Add secret"**으로 새로 발급하세요.

### 3. Refresh Token 발급 (본인 컴퓨터에서 한 번만)

```bash
cd channel_rush22
pip install -r scripts/requirements.txt
python scripts/get_refresh_token.py --client-id "<ID>" --client-secret "<비밀번호>"
```

브라우저가 열리면 **`@Rush22-i8p`를 관리하는 계정으로** 로그인하고 권한을 허용합니다.

스크립트는 발급받은 토큰을 **그 자리에서 API로 검증하고, 어느 채널에 연결됐는지
이름과 핸들까지 출력합니다.** 다른 계정으로 로그인한 경우 경고가 뜹니다. 성공하면
`channel_rush22/.env.youtube`에 저장됩니다(gitignore 처리되어 커밋되지 않습니다).

출력된 값을 위 표대로 GitHub Secrets에 등록하세요.

> `invalid_grant` 오류는 대부분 토큰을 옮겨 적다 생긴 오타입니다.
> `✅ Refresh token verified working` 줄이 떴는지 먼저 확인하세요.

### 4. 동작 확인

저장소 → Actions → **"Rush22 Daily Shorts"** → **Run workflow**.
로그에 `🔒 Verified channel:`과 `✨ Success! https://youtube.com/shorts/...`가
나오면 정상입니다.

## 로컬에서 직접 돌려보기

```bash
cd channel_rush22

# 업로드 없이 영상만 만들어 보기 (자격증명 불필요)
python scripts/generate_video.py --dry-run

# 특정 항목만 렌더링
python scripts/generate_video.py --dry-run --id R017
```

`--dry-run`은 `channel_rush22/output/`에 mp4를 남기고 업로드와 로그 기록을
건너뜁니다. 콘텐츠 뱅크에 문구를 추가한 뒤 길이와 줄바꿈을 확인할 때 쓰세요.

## 콘텐츠 추가하기

`scripts/content_bank.json`에 항목을 덧붙이면 됩니다. 채널 주제를 통째로
바꾸고 싶다면 이 파일만 교체하면 되고 코드는 건드릴 필요가 없습니다.

```json
{
  "id": "R061",
  "topic": "배지에 들어갈 짧은 라벨",
  "hook": "스크롤을 멈추게 하는 한 줄 질문.",
  "body": "두세 문장으로 된 설명. 60~110자 정도가 적당합니다.",
  "punch": "한 줄 결론.",
  "tags": ["태그1", "태그2", "태그3", "태그4"]
}
```

- `id`는 중복되면 안 됩니다. 중복 시 `used_log.csv` 기준으로 이미 쓴 것으로
  간주되어 건너뜁니다.
- 세 문구를 합쳐 **한글 약 300자를 넘기면 60초를 넘겨** 쇼츠로 취급되지
  않습니다. 생성 스크립트가 60초 초과 시 업로드 전에 실패시키므로 조용히
  잘못 발행되는 일은 없지만, 추가 후 `--dry-run`으로 한 번 확인하는 게 좋습니다.
- `tags`의 앞 4개가 설명란 해시태그로 들어갑니다.

## 음성

edge-tts(마이크로소프트 신경망 음성)를 씁니다. **API 키도, 월 한도도, 결제도
없습니다.** 기본 목소리는 `ko-KR-InJoonNeural`(차분한 남성)이고, 워크플로우에
환경변수를 넣어 바꿀 수 있습니다.

| 환경변수 | 기본값 | 설명 |
|---|---|---|
| `RUSH_VOICE` | `ko-KR-InJoonNeural` | `ko-KR-SunHiNeural`(여성) 등으로 변경 가능 |
| `RUSH_VOICE_RATE` | `+12%` | 말 속도 |

> 참고: edge-tts는 일부 클라우드 IP에서 음성 서버가 403을 반환합니다.
> **GitHub Actions 러너에서는 정상 동작하는 것을 확인했습니다.** 개인 서버나
> VPS에서 돌릴 때 403이 나온다면 그건 코드 문제가 아니라 IP 문제입니다.

## 알아두면 좋은 제약

**수익화 조건** — 쇼츠만으로 유튜브 파트너 프로그램에 들어가려면 구독자 1,000명과
**90일간 쇼츠 조회수 1,000만 회**가 필요합니다(롱폼 시청시간 4,000시간 경로와
택일). 하루 2편 자동 발행만으로 5개월 안에 도달할 가능성은 낮습니다. 광고 수익
외의 경로를 함께 깔아야 하는 이유이고, 그 순서는 [`ROADMAP.md`](ROADMAP.md)에
정리해 두었습니다.

**커스텀 썸네일** — 전화번호 인증이 안 된 채널은 썸네일 업로드가 막힙니다.
쇼츠는 썸네일 없이도 정상 노출되므로 지금 구조에서는 문제가 되지 않습니다.

**금융 콘텐츠 면책** — 설명란에 정보 제공용이며 투자 권유가 아니라는 문구가
자동으로 들어갑니다. 콘텐츠를 추가할 때도 특정 상품 추천이나 수익률 보장으로
읽힐 표현은 피하세요. 유튜브 금융 정책과 광고주 친화성 양쪽에 걸립니다.
