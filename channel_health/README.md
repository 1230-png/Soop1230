# channel_health — 채널이 스스로를 보는 자리

필수조건 6번("각 채널마다 부족한 부분은 스스로 업데이트 하면서 성장")을 받치는
계측 층이다. 그동안 이 저장소에는 **어떤 영상이 어떻게 됐는지 아는 코드가
하나도 없었다.** `CLAUDE.md` 에 `metrics.csv` 가 append-only 기록이라고 적혀
있었지만 그 파일을 쓰는 코드가 없었다. 그래서 지금까지의 개선은 전부 추측이었다.

## 하는 일

```bash
python3 collect.py                      # 지표를 metrics.csv · channel_stats.csv 에 덧붙인다
python3 report.py                       # 무엇이 부족한지 한국어로 적는다
python3 collect.py --channel moneylogic # 한 채널만
```

기록은 두 파일로 나뉜다. `metrics.csv` 는 **영상마다** 한 줄이고,
`channel_stats.csv` 는 **채널마다** 한 줄(구독자 수)이다. 구독자는 영상에
붙는 값이 아니라 줄마다 반복할 자리가 없고, 이미 쌓인 파일에 칸을 늘리면
예전 줄(9칸)과 새 줄(10칸)이 섞여 통째로 어긋난다. 둘은 같은 `observed_at`
으로 묶여 있어 "이때 구독자가 몇이었나"를 짝지을 수 있다.

`collect.py` 는 **읽기만 한다.** 업로드도 수정도 댓글도 하지 않는다. 업로드하는
코드와 같은 자격 증명을 쓰기 때문에, 여기에 쓰기 호출이 하나라도 들어오면 그
순간 이 폴더가 발행 경로가 된다 — "읽기만 하니까 안전하다"는 전제로 cron 을
걸어 뒀으므로 그 전제를 깨지 말 것.

## 덮어쓰지 않고 쌓는다

한 번 돌 때마다 그 시점의 값을 한 벌 통째로 남긴다. 영상마다 값을 덮어쓰면
"지금 몇 회"만 남고 "얼마나 늘고 있나"가 사라진다. 늘어나는 속도가 있어야
지난주에 바꾼 것이 먹혔는지 알 수 있다. `used_log*.csv` 와 같은 append-only
기록으로 다룬다 — 정리하거나 되돌리지 말 것.

## 수익화까지 얼마나 남았나

`monetization.py` 가 매 보고서에 두 단계까지의 거리를 적는다. 요건 표의
원본은 `channel_200y3b/scripts/channel_fix.py` 의 `cmd_status` 인데, 그것은
**손으로 돌려야** 하고 **@200-y3b 한 채널만** 본다. 매주 자동으로 도는
자리에 같은 계산이 필요해서 사본을 뒀다(다른 프로젝트를 import 하지
않으므로 — 아래).

| 단계 | 구독자 | 시청 시간(12개월) | 대안 |
|---|---|---|---|
| 초기 수익 창출 (팬 후원·쇼핑) | 500 | 3,000시간 | 숏폼 300만 회/90일 |
| 정식 파트너 (광고 수익) | 1,000 | 4,000시간 | 숏폼 1,000만 회/90일 |

구독자와 시청 시간 중 **어느 쪽이 더 먼지**도 같이 적는다. "373명 부족"과
"2,950시간 부족"은 단위가 달라 그냥은 비교되지 않아서, 목표 대비 비율로
견준다. 견줄 때는 비관 쪽(시청률 20%)을 쓴다 — 낙관 쪽으로 견주면 "시청
시간은 거의 다 됐다"고 말해 놓고 다음 주에 뒤집힌다.

### 그 시청 시간은 추정치다

Data API 에 시청 시간이 없어서 `조회수 × 길이 × 가정 시청률` 로 짐작한다.
**한 값이 아니라 구간으로 내는 이유가 이것이다** — 한 값으로 적으면 그
값이 사실처럼 읽힌다. 오차는 한쪽으로만 나지도 않는다:

- 가정 시청률이 실제보다 높으면 **부풀려진다.**
- 12개월보다 전에 올린 영상이 이번 달에 받은 조회수는 유튜브 기준으로는
  집계에 들어가지만 여기서는 통째로 빠진다. 이쪽은 **모자라게 나온다.**

두 오차가 서로를 상쇄한다고 볼 근거가 없다. 이 숫자로 "이제 곧 된다"를
판단하지 말 것.

## 이 숫자로 말할 수 없는 것

**시청 시간을 모른다.** Data API 가 주는 것은 조회수·좋아요·댓글 수까지다.
파트너 프로그램이 세는 3,000시간은 YouTube Analytics API 에 있고, 그쪽은
`yt-analytics.readonly` 스코프를 따로 받아야 한다. 지금 토큰에는 없다.

숏폼은 조회수가 잘 늘면서 그 3,000시간에는 들어가지 않는다. 그래서
"숏폼 조회수가 올랐다 → 수익화가 가까워졌다"는 **정확히 반대로 읽는 것이다.**
보고서 끝에 매번 이 문장을 붙이는 이유다.

읽고 싶다면 토큰을 다시 발급해야 한다:

```bash
python3 ../channel_200y3b/scripts/get_refresh_token.py \
    --client-secret-file client_secret.json --with-analytics
```

같은 재발급으로 `force-ssl` 도 함께 들어온다. 지금 쇼츠 업로드마다
롱폼 안내 댓글이 `403 insufficientPermissions` 로 실패하고 있는데(경고로
찍히고 넘어가서 눈에 안 띈다), 그것도 같이 풀린다. 한 번 다시 받으면 둘이
같이 해결된다.

## 다른 프로젝트를 import 하지 않는다

이 저장소는 디렉터리마다 독립이다(`CLAUDE.md`). 여기가 남의 코드를 끌어
쓰면 그쪽을 고칠 때 이 폴더가 같이 깨진다. 채널 ID 처럼 겹치는 값은
`channels.py` 에 사본을 두고 원본 위치를 적어 뒀다. 이 폴더를 통째로 지워도
발행 파이프라인은 그대로 돈다.
