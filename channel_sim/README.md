# channel_sim — 「돌려 보는 알고리즘」

계산이 돌아가는 것을 그대로 보여 주는 롱폼 채널. 음성 합성도 배경음악도
쓰지 않는다. 화면과 소리 전부 그 자리에서 계산해 만든다.

```bash
python3 channel_sim/build.py --episode E01 --preview   # 꼭지마다 3초, 확인용
python3 channel_sim/build.py --episode E01             # 본편 (약 13분)
python3 channel_sim/upload.py --dir channel_sim/build/2026-09-21-E01
cd channel_sim && python3 -m pytest                    # 네트워크 안 탄다
```

## 왜 이 형식인가

앞선 두 시도가 같은 자리에서 막혔다. 슬라이드에 합성 음성을 얹으면 3초 안에
자동 생성물로 분류된다. 유튜브가 거르는 것은 "기계가 만들었다"가 아니라
**"틀을 반복 재생산했다"**이고, 슬라이드에 글자만 갈아 끼우는 것이 정확히
그것이다.

여기서는 매 편 실제로 다른 계산이 돈다. 소재를 고를 때 첫 번째 기준이
**"화면에 나오는 것이 통째로 달라지는가"**다.

그리고 길이에 명분이 있다. 버블 정렬이 384개를 정리하는 데 걸리는 시간이 곧
그 꼭지의 길이다 — 늘린 것이 아니라 원래 그만큼 걸린다. 롱폼이어야 하는
이유는 따로 있다: **숏폼 시청 시간은 파트너 프로그램의 3,000시간에 집계되지
않는다.** 앞 채널이 61일 동안 숏츠로 13,848회를 모으고도 시청 시간 기여가
사실상 0이었다.

## 구조

| 파일 | 하는 일 |
|---|---|
| `lib/algos.py` | 정렬 12종. 결과가 아니라 **사건의 열**을 내놓는다 |
| `lib/frames.py` | 화면. PIL 이 아니라 numpy 로 그린다 |
| `lib/audio.py` | 소리. 만지는 값의 높이를 5음 음계에 올린다 |
| `build.py` | 프레임을 ffmpeg 로 흘려보내고 소리와 합친다 |
| `upload.py` | `SIM_*` 전용. 대체 자격 증명 없음 |
| `channel.yaml` | 채널 이름·설명·키워드, 앞으로 만들 10편 |

### 사건이 두 종류뿐인 이유

`("compare", i, j)` 와 `("write", i, j)`. 이 둘만 있으면 어떤 알고리즘이든
같은 방식으로 그릴 수 있고, **비교 횟수와 쓰기 횟수를 공짜로 세게 된다.**
영상 끝의 순위표가 그 숫자이고, 그 두 줄의 순서가 서로 다른 것이 이 편의
결론이다 — 선택 정렬은 비교로 줄을 세우면 꼴찌권인데 쓰기로 세우면 1등이다.

### numpy 로 그리는 이유

PIL 로 막대 384개를 매 프레임 그리면 13분짜리(23,000프레임)에서 그리기만
몇십 분이 든다. 막대는 결국 직사각형이라 색 배열 하나를 브로드캐스트하면
한 번의 연산으로 끝난다. 글자만 PIL 로 그리고, 그마저 꼭지마다 한 번 그려
두고 픽셀을 복사한다.

### 소리를 계산해서 만드는 이유

무음으로 두면 십 초 안에 끈다. 배경음악을 깔면 저작권을 관리해야 하고,
내레이션을 넣으면 이 채널이 피하려는 바로 그 자동 음성이 된다. 그래서
**지금 만지는 값 자체를 소리로 바꾼다.** 반음 단위로 그대로 매핑하면
사이렌처럼 들려서, 5음 음계 위에 올렸다 — 20분을 견디게 만드는 것이 그
한 줄이다.

## 한 번 데인 자리

**사건을 실수 빚으로 소화하지 말 것.** 프레임당 개수를 실수로 들고 다니며
빚을 갚는 방식으로 짰더니 마지막 프레임에서 사건이 하나 남았다. 제너레이터는
게을러서 그 한 번의 `next()` 안에 마지막 대입이 들어 있다 — 안 부르면 배열이
정렬되지 않은 채로 영상이 끝난다. 삽입 정렬이 실제로 그렇게 실패했고,
**영상은 정상으로 보이고 업로드도 된다.** 누적 목표로 바꿨고
`tests/test_schedule.py` 가 그 성질을 못 박는다.

**퀵 정렬의 축은 가운데로.** 맨 끝을 축으로 잡는 교과서 판은 이미 정렬된
입력에서 O(n²)로 떨어지고 재귀가 n 단계로 깊어져 `RecursionError` 가 난다.
`tests/test_algos.py` 의 구석진 입력 검사가 그 자리다.

**표시할 칸은 최근 것만.** 버블 정렬은 한 프레임에 서른 번 넘게 비교한다.
그걸 전부 칠하면 이미 정렬된 왼쪽 절반이 통째로 흰색이 되어 무엇이 정렬됐는지가
안 보인다.

## 비밀값

**환경변수로만. 코드·커밋·로그에 절대 넣지 않는다.**

`SIM_CLIENT_ID` / `SIM_CLIENT_SECRET` / `SIM_REFRESH_TOKEN` / `SIM_CHANNEL_ID`.

**대체 경로를 두지 않는다.** `longform/upload.py:40` 은 `Y3B_*` 가 비면 공용
`YT_*` 로 넘어가는데, 시크릿을 깜빡한 날 남의 채널로 조용히 올라간다. 여기는
없으면 멈춘다. 유튜브 일일 할당량도 채널이 아니라 **구글 클라우드 프로젝트
단위**라 돌려쓰면 서로의 몫을 깎는다 — 이 채널은 제 프로젝트를 쓴다.

리프레시 토큰은 `get_refresh_token.py` 를 **본인 컴퓨터에서** 한 번 돌려
받는다. 구글 클라우드 동의 화면이 "테스트"로 남아 있으면 7일 뒤 토큰이
폐기되므로 프로덕션으로 게시할 것.
