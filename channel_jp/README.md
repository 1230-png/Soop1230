# 귀트는 일본어 (channel_jp)

한국어 화자를 위한 **일본어 듣기 롱폼** 채널. 머니로직을 접은 자리를 쓴다.

## 왜 롱폼이고 왜 일본어인가

숏폼 시청 시간은 파트너 프로그램의 3,000시간에 **집계되지 않는다.** 머니로직은
28일에 조회수 8,414회를 받고도 시청 시간이 14.8시간이었다 — 99.5%가 숏폼이라
받은 트래픽이 세지지 않는 그릇에 담긴 것이다. 30분 영상을 40% 지속률로 보면
1회당 12분이 쌓이고, 3,000시간까지 필요한 조회수가 180만에서 1.5만으로 내려간다.
**형식이 주제보다 먼저다.**

일본어인 이유는 세 가지다. `longform/`(@200-y3b 영어)의 파이프라인이 그대로
재사용되고, 청중이 겹치지 않아 기존 채널을 깎지 않고, edge-tts 가 무료다.

## 왜 `longform/` 을 고쳐 쓰지 않았나

`longform/` 은 **가동 중이다.** 매일 @200-y3b 에 무인 발행한다. 거기에 언어
분기를 넣으면 일본어 쪽 실수가 영어 쪽 발행을 멈출 수 있다. 이 저장소는
디렉터리마다 독립이라는 규칙을 그래서 두고 있다(CLAUDE.md).

대신 코드가 겹친다. 그 값은 치르기로 한 것이다 — 겹친 코드는 한쪽이 깨져도
다른 쪽이 돌지만, 얽힌 코드는 같이 멈춘다.

## 문장 은행

```bash
python3 channel_jp/build_bank.py            # 검사하고 data/phrases.json 을 쓴다
python3 channel_jp/build_bank.py --check    # 검사만 (파일을 쓰지 않는다)
cd channel_jp && python3 -m pytest          # 검사기 자체의 테스트
```

`data/_parts/*.json` 이 원본이다. 주제별로 나눠 둔 이유는 300개를 한 파일에 두면
**사람이 검수를 못 하기 때문**이다. 파일 이름 순서가 곧 영상에서의 순서다.

`data/phrases.json` 은 **생성물이다.** 직접 고치지 말고 조각을 고쳐 다시 만든다.

### 은행을 늘릴 때는 뒤에 붙인다

번호(J001…)는 **조각 파일 이름순으로 센 위치**로 매겨진다. 그래서 앞쪽 조각에
문장을 하나 끼워 넣으면 그 뒤가 전부 한 칸씩 밀리고, `used.json` 에 적힌 J001
이 **다른 문장**을 가리키게 된다. 이미 발행한 편의 "쓴 문장"과 "안 쓴 문장"이
통째로 뒤바뀌는데, 영상은 멀쩡해 보이고 아무도 모른다.

그래서 **기존 조각은 건드리지 말고, 뒤에 오는 이름으로 새 파일을 만든다.**
`13-인사2.json`, `14-자기소개2.json` … 이 그렇게 붙인 것이다. 주제(`topic`)는
기존 것과 같은 값을 쓰면 되고, 파일이 나뉜 것은 순서와 검수 편의 때문이지
주제가 달라서가 아니다.

`build_bank.py` 가 직전 `phrases.json` 과 대조해서, 이미 나간 번호의 뜻이
바뀌면 **파일을 쓰지 않고 멈춘다.** 워크플로에서는 이 검사가 ElevenLabs 를
부르기 전에 서므로 돈이 나가기 전에 걸린다.

### 검사기가 막는 것

머니로직은 제목에 `nan%` 가 박힌 영상을 여드레 동안 공개로 올렸다. 원인은
`float('nan') >= 0` 이 False 인 것이었지만, 진짜 문제는 **깨진 값이 발행까지
흘러간 것**이다. 그래서 이 검사는 영상 파이프라인 앞에 선다.

- 빈 칸 — 카드에서 빈 줄이 된다
- `ja`·`ex_ja` 에 한글 — TTS 가 일본어 음성으로 한글을 읽으려다 무음이 된다
- `yomi`·`ko` 에 가나·한자 — 카드에 그대로 찍히고 학습자는 한글인 줄 안다
- 같은 일본어 문장 중복 — 지우되 **몇 개가 사라졌는지 말한다**

마지막 항목이 조용하면, 150문장을 넣었는데 영상이 짧아진 이유를 찾을 수 없다.

초안 300개에서 이 검사가 실제로 세 건을 잡았다: `ja` 칸에 들어간 한국어 문장,
읽기 칸에 남은 `ん` 한 글자, 예문에 섞여 들어간 `three年`.

## 영상 만들기

```bash
python3 channel_jp/build.py --pack sleep_japanese --offline --limit 6   # 빠른 시험
python3 channel_jp/build.py --pack sleep_japanese --offline             # 길이까지 확인
python3 channel_jp/build.py --pack sleep_japanese                       # 진짜 (돈이 든다)
```

`--offline` 은 TTS 대신 무음을 넣는다. 네트워크도 API 키도 돈도 쓰지 않고
타이밍·카드·이어붙이기·인코딩을 전부 확인할 수 있다. `used.json` 도 건드리지
않는다 — 건드리면 다음 진짜 빌드에서 그 문장들이 이미 쓴 것으로 빠진다.

팩은 셋이다.

| 팩 | 길이 | 문장 | 언제 |
|---|---|---|---|
| `sleep_japanese` | 40분 | 150 | 금 |
| `situation_pack` | 14분 | 30 | 화 |
| `shadowing_drill` | 24분 | 45 | 목 |
| `sleep_japanese_long` | 3시간 | 700 | 토 |

`sleep_japanese` 가 주력이다. 사람들이 틀어 놓고 자기 때문에 1회당 시청
시간이 가장 길다.

## 목소리 — ElevenLabs

`ELEVENLABS_API_KEY` 환경변수로만 들어온다. **키가 없으면 멈춘다.** edge-tts
로 되돌아가지 않는다 — 되돌아가게 두면 어느 날 키가 만료됐을 때 목소리가
통째로 다른 영상이 조용히 올라간다. 채널 자격 증명에 대체 경로를 두지 않는
것과 같은 이유다.

음성 ID 는 `packs.yaml` 의 `voice_ja` · `voice_ja_alt` · `voice_ko` 에 있고
지금은 셋 다 같은 값이다. 다국어 모델(`eleven_multilingual_v2`)이라 한
목소리가 일본어와 한국어를 모두 읽는다. 나눌 일이 생기면 `voice_ko` 만
바꾸면 되고 코드는 안 건드려도 된다.

**느린 읽기에 값을 두 번 내지 않는다.** ElevenLabs 는 글자 수로 받는데,
같은 문장을 속도만 바꿔 두 번 보내면 값이 그대로 두 배다. 대신 보통 속도
음성을 받아 ffmpeg `atempo` 로 늦춘다. 음높이는 그대로고 글자 값은 한 번만
든다 — 수면 팩 한 편 기준으로 대략 4,400자가 3,300자로 내려간다.

한 편에 드는 글자 수(대략):

| 팩 | 글자 |
|---|---|
| `sleep_japanese` | 약 3,300 |
| `situation_pack` | 약 1,400 |
| `shadowing_drill` | 약 1,600 |

주 3편이면 한 달에 대략 25,000자다. 요금제를 고르기 전에 이 숫자를 볼 것.

## 쇼츠

```bash
python3 channel_jp/shorts.py --offline      # 무음으로 시험 (used.json 안 건드림)
```

`channel_jp_shorts.yml` 이 하루 3편을 낸다. 한 편에 문장 하나, 약 10초 세로
영상이다 (일본어 → 뜻 → 느리게 → 다시). 올리기는 롱폼과 같은 `upload.py` 다.

**구독자를 데려오려고 낸다. 시청 시간은 벌지 않는다** (위 「왜 롱폼이고」).
그래서 설명란이 롱폼 재생목록을 가리킨다. 문장 기록은 `used.json` 의
`packs.shorts` 에 따로 쌓여, 903문장이면 300일을 간다. 한 편에 드는
ElevenLabs 글자는 ja + ko 정도(30자 안팎)라 한 달 약 2,700자다.

## 카드

배경은 밝고, **진행 막대를 두지 않는다.** 화면 아래 가로 막대는 재생 바로
읽혀서 시청자가 영상이 멈춘 줄 알고 화면을 건드린다. 남은 분량은 오른쪽 위
`1 / 150` 이 이미 말해 준다.

순백을 쓰지 않는 이유는 자기 전에 트는 영상이기 때문이다. 어두운 방에서
화면만 하얗게 타오르면 눈이 아프다.

### 폰트

`lib/cards.py` 의 `find_font()` 는 **목록 순서로 고르지 않는다.** 후보마다
히라가나·가타카나·한자·한글을 실제로 그려 보고, 없는 글자가 하나라도 있으면
넘어간다.

이 검사가 없으면 조용히 깨진다. PIL 은 없는 글자를 만나도 예외를 내지 않고
.notdef(빈 칸이나 네모)를 그냥 그린다. 이 러너에서 실제로 확인한 것:

| 폰트 | 없는 문자 |
|---|---|
| NotoSansCJK | 없음 (쓸 수 있다) |
| fonts-japanese-gothic | 한글 |
| NanumGothic | 히라가나, 가타카나, 한자 |
| DejaVuSans | 전부 |

나눔고딕이 먼저 잡히면 일본어가 통째로 □ 로 나간다. 러너에는
`fonts-noto-cjk` 가 있어야 한다.

## 발행 차단

머니로직은 제목에 `nan%` 가 박힌 영상을 여드레 동안 공개로 올렸다. 원인은
`float('nan') >= 0` 이 False 라 항상 "하락"으로 갈라진 것이었지만, 진짜
문제는 깨진 값이 아무 저항 없이 발행까지 흘러간 것이다. 그래서 두 번 막는다.

**합성 전** (`verify_phrases`) — 고른 문장이 온전하지 않으면 edge-tts 든
ElevenLabs 든 한 번도 부르지 않고 멈춘다. 돈이 드는 단계 앞에 검사를 둔다는
CLAUDE.md 규칙과 같은 자리다.

**인코딩 후** (`verify_publishable`) — 하나라도 걸리면 0 이 아닌 코드로
끝난다. 파일은 남겨 둔다(무엇이 잘못됐는지 봐야 고치므로) 워크플로의 업로드
단계만 돌지 않는다.

- 제목·설명에 `nan` · `None` · `null` · 안 채워진 `{자리}`
- 영상에 들어간 문장이 0개
- 길이가 60초 미만
- `target_minutes` 에서 30% 넘게 벗어남 (`--limit` 실행은 제외)

경계를 `\b` 로 잡지 않는다. 파이썬의 `\b` 는 유니코드 기준이고 한글도 단어
문자라서 「문장 None개를 모았습니다」가 그냥 지나간다 — 깨진 값이 한국어
문장에 박힌 바로 그 모양인데. 좌우를 로마자만으로 막아서, 「난바(nanba)」
같은 멀쩡한 제목은 걸리지 않고 「None개」는 걸린다.

## 공개 설정

`build.py` 는 `metadata.json` 에 `privacyStatus: private` 를 적는다. 근거는
머니로직이다 — 그 채널은 **사람 확인 없이** 공개로 여드레 동안 제목에 `nan%`
가 박힌 영상을 냈다.

그 장치가 막으려던 것은 **무인 발행**이지, 사람이 버튼을 눌러 돌리고 결과를
보는 경우가 아니다. `channel_jp.yml` 에는 cron 이 없어서 누군가 누르지 않으면
한 편도 나가지 않는다. 그리고 비공개 영상은 시청 시간이 0이라, 확인을
기다리며 쌓아 두는 쪽에도 대가가 있다.

그래서 세 편을 내 보고 **워크플로의 `privacy` 기본값을 `public` 으로** 바꿨다.
`build.py` 가 `metadata.json` 에 적는 값은 `private` 그대로다 — 손으로
`upload.py` 를 부를 때의 보수적인 기본이고, 워크플로는 `--privacy` 로 그것을
덮어쓴다.

**사람이 영상을 보고 공개하던 단계가 이제 없다.** 발행을 막는 것은
`verify_publishable` 하나뿐이고, 그것이 보는 것은 깨진 값·빈 문장·길이다.
**소리가 나는지는 아무도 보지 않는다** — 무음 35분도 이 검사를 전부 통과한다
(실제로 이 세션의 재현 시험이 그런 파일을 만들었다). 되돌리려면 워크플로의
기본값을 `private` 으로 바꾸면 된다.

## 발행 일정

`channel_jp.yml` 이 주 3편을 무인으로 낸다. 요일은 `packs.yaml` 의 `schedule`
과 맞춰 뒀지만 **그 값을 읽는 코드는 없다** — 실제 스케줄은 워크플로의 cron 이고,
어느 cron 이 어느 팩인지는 「이번 회차 설정」 단계의 `case` 가 정한다. 둘을
같이 고칠 것.

| 요일 (KST) | 팩 | 길이 | 한 편에 쓰는 문장 |
|---|---|---|---|
| 화 21:00 | 상황별 | 14분 | 30 |
| 목 21:00 | 쉐도잉 | 24분 | 45 |
| 금 21:00 | 수면 | 40분 | 150 |

다섯 편(수면 3 · 상황별 2)을 손으로 내 보고 걸었다. 쉐도잉은 발행 전
계산으로 19.8분을 예상했다(같은 모형이 상황별 두 편을 오차 2.4% 안에서
맞혔다). 되돌리려면 `on.schedule` 을 지우면 된다 — 손 실행은 그대로 남는다.

**수면 팩이 이 속도의 발목이다.** 한 주에 225문장을 쓰는데 그중 150이
수면 팩 몫이다. 은행을 903개까지 늘려도 수면 팩은 3주치이고, 쉐도잉은
20주 · 상황별은 28주다. 300개를 더 써도 수면 팩은 2주가 늘 뿐이라,
**손으로 쓰는 속도가 주 150문장을 못 따라간다.**

**그래서 수면 팩의 재사용은 받아들이기로 했다(2026-09).** 재사용은 설계된
동작이라 멈추지 않고, 오래된 것부터 골라 고르게 퍼뜨린다. 수면 팩은 틀어
놓고 자는 형식이라 같은 문장이 다시 나오는 것이 학습에서 손해가 아니고,
대안 둘(주기를 격주로 늘리기 · `phrase_count` 줄이기)은 **시청 시간을 직접
깎는다.** 이 채널이 쌓으려는 것이 그 시간이므로 그쪽을 택하지 않았다.

다시 꺼낼 만한 신호는 하나다 — 수면 팩의 시청 지속률이 회차를 거듭하며
떨어지면 반복이 실제로 손해라는 뜻이다. 그때는 위 두 대안을 다시 볼 것.
지금은 근거가 없어서 정하지 않았다(`channel_health` 는 조회수만 읽는다).

조각을 더 넣는 방법은 위 「은행을 늘릴 때는 뒤에 붙인다」를 볼 것 — 은행을
늘리는 것은 여전히 도움이 되지만, 주 150문장을 따라잡지는 못한다.

## 토큰 재발급 (시청 시간·지속률을 열려면)

지금 `MV_REFRESH_TOKEN` 에는 `yt-analytics.readonly` 가 없다. 그래서
`channel_health` 가 읽는 것은 **조회수까지**이고, 파트너 프로그램이 세는
시청 시간과 지속률은 안 보인다. 「수면 팩이 반복돼도 괜찮은가」 같은 질문에
숫자로 답하려면 이것이 필요하다.

**순서를 지킬 것 — 1번을 건너뛰면 발급 자체가 실패한다.**

1. 구글 클라우드 콘솔 → **OAuth 동의 화면 → 범위**에
   `https://www.googleapis.com/auth/yt-analytics.readonly` 를 추가한다.
   **이 채널이 쓰는 프로젝트에서** 해야 한다 — 머니로직 때 쓰던 그
   프로젝트이고, `channel_200y3b` 것과 다르다.
2. 동의 화면 게시 상태가 **"테스트"** 면 테스트 사용자에 이 채널을 관리하는
   계정이 들어 있어야 한다.
3. 본인 컴퓨터에서 (CI 아님):

   ```bash
   pip install google-auth-oauthlib
   python3 channel_jp/get_refresh_token.py        --client-id "...apps.googleusercontent.com"        --client-secret "GOCSPX-..." --with-analytics
   ```

   브라우저에서 **「귀트는 일본어」를 관리하는 계정**으로 로그인하고,
   동의 화면에서 **항목을 하나도 끄지 않는다.**
4. 찍힌 `MV_REFRESH_TOKEN` 을 저장소 Secrets 에 갈아 끼운다.
   (Settings → Secrets and variables → Actions)
5. 「귀트는 일본어 — 채널 설명·키워드」 워크플로를 **dry-run 으로** 한 번
   돌린다. 토큰이 멀쩡한지 돈 안 쓰고 확인된다.

`channel_200y3b/scripts/get_refresh_token.py` 를 쓰지 말 것. 저쪽은 `Y3B_`
이름으로 찍고 저쪽 채널로 로그인하라고 안내한다.

**새 토큰이 지금보다 좁아지면 안 된다.** 스크립트가 요청하는
`youtube.force-ssl` 은 지금 쓰는 권한의 상위 집합이라 업로드·재생목록·썸네일이
그대로 된다. 동의 화면에서 항목을 끄면 다음 화요일 cron 이 재생목록에서
403 으로 죽는다.

**토큰만 바꾼다고 숫자가 나오지는 않는다.** `channel_health/collect.py` 는
Data API 만 부른다 — Analytics API 를 읽는 코드는 아직 없다. 스코프는 그
코드를 쓸 수 있게 하는 전제 조건이고, 읽어 오는 것은 따로 만들어야 한다.

## 비밀값

**환경변수로만 다룬다. 코드·커밋·로그에 절대 넣지 않는다.**

- `ELEVENLABS_API_KEY` — 음성. 없으면 빌드가 멈춘다
- `MV_CLIENT_ID` / `MV_CLIENT_SECRET` / `MV_REFRESH_TOKEN` / `MV_CHANNEL_ID`
  — 유튜브 업로드

**`MV_` 는 머니로직에서 온 글자지만 그 채널은 없다.** 이름을 바꾼 것이지
지운 것이 아니라서 같은 유튜브 채널이 지금 「귀트는 일본어」다. 채널 이름을
바꿔도 채널 ID 는 그대로이므로 이 자격 증명이 그대로 맞는다.

접두사를 안 바꾼 이유는 **GitHub 시크릿의 값을 다시 읽을 수 없기 때문이다.**
새 이름을 만들려면 구글 클라우드에서 client_id/secret 을 다시 받고 리프레시
토큰도 재발급해야 한다. 글자 네 개 때문에 치를 값이 아니다.

공용 `YT_*` 와 채널푸드의 `WEIRD_*` 는 쓰지 않는다 — 그쪽은 정말 남의
것이다.
